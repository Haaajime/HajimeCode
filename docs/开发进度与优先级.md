# 开发进度与优先级（Hajime2Code）

> 模块级进度与排队依据。完整技术方案见 `../../项目方案/新项目方案_Hajime2Code.md`。
> 优先级说明：**P0** 主线骨架 / **P1** 简历核心卖点 / **P2** 增强项。
> 具体问题（文档漂移 / 未验证项 / 技术债）见 `known_issues.md`。

## 当前方向（2026-09-28 调整）

**产品优先，评测后置。** 先把它做成一个**成熟的产品**，再谈量化。

- **成熟的目标线**：**在一个真实仓库上端到端修好一个真实 issue**——能读代码、改代码、跑测试、断点续跑、可人工审批。跨过这条线才谈得上"产品"。
- **评测处置**：**完全后置**。E1–E4 在目标线达成后再排；此前不碰指标。
- **零浪费的做法**：产品验收用的真实 issue 按 `benchmarks/<id>/meta.json` 规范沉淀，即为日后任务集 —— 同一批任务先用于"能不能修好"，后用于"哪种机制更好"。
- **不再适用的原条款**：方案 §10 风险 3 的对策原文是「**实验优先于功能**」，与当前方向相反，已在方案中改写。
- **第 0 步（已完成）**：真实模型冒烟。结果：主图原本在 `plan` 节点就 400（`with_structured_output` 默认 `json_schema` 不被 DeepSeek 支持），已修复并跑通端到端。详见 `known_issues.md` 已修复第一条。
