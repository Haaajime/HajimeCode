# 开发规范（Agent Harness 项目）

> 本文件为项目固定约定。违反任一条时,应先在文档或本文件中补记录,再执行。所有团队/协作相关新约定优先写到这里。

## 1. 环境与工具

- 使用 **uv** 管理 Python 项目与虚拟环境（当前 Python **3.10**）。
- 依赖一律声明在 `pyproject.toml`，通过 `uv add / uv run` 使用，禁止手动 `pip install`。
- 进入/校验环境用 `uv sync`；不在环境中安装未声明的包。

## 2. git 管理规范（强制）

- 使用分支 **`main`** 作为唯一主分支；按"一个逻辑工作单元 = 一次提交"提交，不把无关改动混进一次 commit。
- **每完成一项工作**，必须同时：
  1. 在 `docs/开发日志.md` 追加一条记录（日期/内容/改动文件/测试结果/commit）；
  2. 执行一次 git commit（提交信息尽量聚焦该单元）。
- Commit message 约定（Conventional Commits 精简版）：
  `type(scope): subject`，如 `feat(permission): 新增权限白名单层`、`test(loop): 补充未知工具用例`。
  type 常用：`feat` / `fix` / `test` / `docs` / `refactor` / `chore`。
- **禁止提交敏感信息**：`*.env`、密钥、token 一律不进入 git（见 .gitignore）；确有需要提供 `*.env.example`。
- 提交前必须本地跑通 `uv run pytest -q`。

## 3. 代码规范

- 不写废话注释：只对"为什么这样"加注释，命名本身说明"做了什么"。
- 保持模块单一职责：权限归 `permissions.py`，循环归 `loop.py`，工具归 `tools.py`，新增机制尽量分文件。
- 外部依赖只在使用时最小化引入。

## 4. 测试规范

- 每个新功能必须有 **mock/离线单测**（`tests/` 下 `test_*.py`），**不消耗真实 API**。
- 真实模型 API 仅用于**极小 token 的冒烟验证**，且要在开发日志中记录；不要为调试反复消耗线上 token（遵守"节省"原则）。

## 5. 安全规范

- 密钥只从环境变量/`.env` 读取（见 `config.py`），严禁硬编码进源码。
- 新增危险工具（`bash` 等）必须配 **权限白名单**：默认拒绝高危命令，进入 `ask`/审批流程。
- 权限判定逻辑必须可被单测覆盖,且默认策略从"禁"出发（fail-closed）。

## 6. 记录规范

- `docs/开发日志.md`：按时间追加，记录每个已完成的工作单元（里程碑）。
- `docs/开发规范.md`：本文件，固定约定;变更需在此登记。

## 7. 问题同步

- 开发中遇到环境、设计取舍、方向性疑问等无法自行定夺的问题，**主动向用户（项目负责人）同步并确认**，不擅自跳过。
