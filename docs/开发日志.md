## 2026-09-28 · 文件读取覆盖度：修复两处静默失败 + 建立样例仓库

- **缘起**：用户反馈"第一次亲手跑 HajimeCode 时连正常文件夹读取都做不好"，并担心 Hajime2Code 同样"读不全"（尤其子文件夹）。判断分层为：**读取正确 → 结构组织成 prompt → 模型解决得好坏**，读取是地基。
- **做法**：不靠"看一眼没崩"，而是**与磁盘真相逐条比对**。新建样例仓库 `tests/fixtures/sample_repo/`（39 个条目），刻意覆盖多级子包、4 层深嵌套、隐藏文件、非 ASCII 名、含空格名、空目录、二进制、仓库内/越界符号链接、被忽略目录。
- **发现的失败（两处，均为静默）**：
  1. **工作区路径含 `build`/`dist`/`node_modules` 等名字 → 整个工作区被判为忽略**。`Workspace.is_ignored` 比较的是**绝对路径**的 parts，于是 `glob` 返回 `[]`、`list_dir` 返回 0 项，而文件确实存在、`read` 也读得到 —— Agent 完全瞎掉。实测复现：同一份仓库放在 `/tmp/.../build/parent/proj` 下返回 0 条，放在 `/tmp/.../normal/parent` 下返回 39 条。
  2. **200 条上限静默截断**。350 个文件时 `glob` 只返回 200 条且**无任何提示**；`list_dir` 表头写"共 350 项"却只列 200 项 —— 模型会据此断定错误的总数。这正是用户说的"读不全"。
- **修复**：
  - `is_ignored` 改为只比较**工作区内的相对部分**。
  - `glob` 改返回 JSON **对象**：`{pattern, returned, total_matched, truncated, paths, hint?}`；`truncated` 为真时附可操作提示。契约变更同步更新 `test_fs_tools.py`。
  - `list_dir` 表头显式标注"**仅显示前 N 项**，另有 M 项未列出"。
  - `read` 遇二进制文件（含 NUL）直接说明并跳过，不再把乱码灌进上下文。
- **新增测试**：`tests/test_fs_coverage.py`（19 条），判据是"与磁盘真相逐条比对"而非"返回非空"。`conftest.py` 加 `collect_ignore_glob = ["fixtures/*"]`，避免样例仓库自带的 `tests/test_*.py` 被 pytest 误收集。
- **真实模型侧对齐检查**（把工作区指向样例仓库跑一次）：总条目 **39 ✓**（= 14 目录 + 25 文件/链接）、`.py` **10 ✓**、隐藏文件 **3 ✓**；分类明细有 off-by-one（目录答 13 实为 14、文件答 26 实为 25、`.md` 答 7 实为 6）。
  → **结论：工具层已正确，偏差出在模型推理层**。模型的另一句抱怨很有价值："工具未暴露链接信息，无法证实是否为符号链接"——这直接指向下一层（结构如何进上下文）。
- **改动文件**：`src/hajime2code/workspace.py`、`src/hajime2code/tools/fs.py`、`tests/conftest.py`、`tests/test_fs_tools.py`、`tests/test_fs_coverage.py`（新增）、`tests/fixtures/sample_repo/`（新增，含 2 个符号链接，git 中为 mode 120000）。
- **测试结果**：`ruff check` 通过 · `ruff format --check` 通过 · `mypy`（27 文件）0 错误 · `pytest` → **83 passed**（原 64）。
- **新登记开放项**（`known_issues.md` 7、8）：
  - `glob` 输出不区分符号链接（模型实测明确抱怨）。
  - **文件结构如何组织成 prompt 尚无机制** —— 只有 `list_dir`（不递归）/ `glob` / `read`，理解结构需多次往返，且无概览 / 目录树工具。这是"读取正确"之后的下一层。

## 2026-09-28 · 调研：代码库结构怎么"进上下文"（否掉目录树方案）

- **缘起**：上一轮结尾我提议"做一个带大小/行数/类型标注的目录树概览工具"来解决"结构进不了上下文"。用户追问：**这真能解决问题吗？是当前公认最佳方案吗？**（不能，就先去调研。）
- **结论：不是。而且我上一轮的诊断本身站不住。** 反证来自我们自己的实测——那次运行模型用**现有 `glob`** 就把样例仓库 **39/39 条全列对了**，错的是分类计数与符号链接识别。目录树这两样都补不上。
- **调研要点**（详见 `docs/调研_代码库结构如何进上下文.md`）：
  - **行业已从"预建索引"转向"按需检索"**：Anthropic 2025-05 把 Claude Code 的整条向量管线（embedding + 本地向量库 + 切块）删掉换成一个 grep，作者称 "outperformed everything, by a lot"；Cursor / Windsurf / Cline / Devin 随后跟进。
  - **实证**：SWE-bench 初版 RAG 基线 **1.96%** → SWE-agent 换成工具调用后 **12.47%**；Amazon AAAI 2026《Keyword Search Is All You Need》纯关键词 Agent 达 RAG 忠实度 **>90%** 且零向量设施。
  - **目录树为何不是答案**：信息密度低（"directory listings … waste tokens on low-signal content"）、在真实仓库规模（平均 **438K 行 / 3010 文件**）不可用、有结构无语义。真正解决规模问题的是 **repo map**（tree-sitter 符号 + PageRank + token 预算二分拟合，Aider 实测 SWE-bench Lite 26.3% / 正确定位文件 70.3%）——**它是符号级排名，不是文件树**。
  - 诚实记录反方：关键词检索是"超过 90%"而非"超过 100%"，索引仍有小幅胜出空间；向量检索适合"自然语言提问 + 海量稳定语料"。
- **由此定位出真正的缺口**（对照我们代码）：
  - ❌ **没有内容搜索工具**（`read`/`list_dir`/`glob`/`write`/`edit` 里没有 grep）—— agentic search 的支柱缺失，**最大缺口**。

## 2026-09-28 · 修复"新前端 + 旧后端"错配：不再静默吞错 + 版本握手

- **用户实测反馈**：打开网页后「模型选择没有任何显示」、「工作目录后面的浏览按钮点击后显示 Not Found」。

  - **8000 端口上跑着一个本次会话之前的临时桩服务**（`/tmp/h2c_stub_server.py`，20:42 启动，比会话开始还早），它的 API 是旧的。

  1. **不再静默吞错**：捕获并显示，区分"版本不兼容"与"加载失败"，给出**可操作指引**（结束旧进程 → 重启 → 刷新）。

  3. **404 可操作化**：`/api/*` 上的 404 不再抛原文 `Not Found`，而是说明"服务端没有接口 X，大概在跑旧版本"。
